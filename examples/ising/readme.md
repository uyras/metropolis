Пример расчета антиферромагнитной модели Изинга на простой квадратной решетке.
----

В этом примере показано как вычислить термодинамику модели Изинга используя программу metropolis.

Изначально программа спроектирована для работы с моделью диполь-дипольного взаимодействия, а координаты диполей и вектор магнитного определяются в 3D пространстве. Если расположить диполи на квадратной решетке в плоскости `X`,`Y` а вектор задавать вдоль оси `Z`, то это будет аналогично антиферромагнитной модели Изинга. Для полного соответствия параметр решетки должен быть 1, должны учитываться только ближайшие соседи (4 соседа у спина), и длина вектора `m`=1. Настроим вычисление такой системы. Будет рассматриваться система с периодическими граничными условиями (ПГУ) по осям X и Y.

Вычисление состоит из следующих шагов:

1. Подготовка системы
2. Создание файла конфигурации
3. Запуск вычислений

# 1. Подготовка системы

Необходимо создать файл `.mfsys`, определяющий конфигурацию системы. Конфигурация определяет позиции всех спинов и направления их магнитных моментов.
В нашем примере спины Изинга будут лежать в узлах простой квадратной решетки вдоль осей `X`,`Y`, а вектор магнитных моментов будет лежать вдоль оси `Z`. Параметр решетки 1, это значит что расстояние между парой ближайших спинов равно 1. Длина вектора магнитного момента тоже равна 1 у всех спинов. При учете диполь-дипольного взаимодействия ближайших соседей, минимальной энергией будет шахматное упорядочение спинов.

В файле [ising_16.mfsys](ising_16.mfsys) пример системы размером $N=16$ спинов, то есть $4 \times 4$ спина, где $L=4$ - линейный размер системы. Он создан скриптом [generator.py](generator.py), который запускается командой `python generator.py 4`. Система создана в ground state, то есть начальная конфигурация определена в шахматном порядке. Следует использовать четное значение $L$, так как при нечетном значении при включенных ПГУ на границах системы соседние спины окажутся сонаправленными. Не будет конфигурации, при которой бы все пары спинов оказались минимизированы.

# 2. Создание файла конфигурации

В файле `ising_16_simple.ini` показан пример конфигурации для простого и максимально быстрого запуска вычислений со следующим содержимым:
```ini
[main]
file = ising_16.mfsys
heatup = 100000
calculate = 1000000
range = 1.01
seed = 123
temperature = 1, 2, 3, 4, 5
boundaries = periodic
size = 4|4
```

Формат файла полностью соответствует классическим ini-файлам. В файле обязательно должна быть секция `[main]` с основными параметрами. Векторные значения указываются как одно число с разделителем `|`. Например `1|2` - двумерный вектор с координатами `x=1` и `y=2`. Либо трехмерный вектор: `3|4|5`. Если требуется указание трехмерного вектора, но указан двумерный (или скаляр), то оставшиеся значения считаются как 0.

* `file` - имя файла
* `heatup` - число прогревных шагов, для приведения системы к термодинамически усредненной конфигурации.
* `calculate` - число вычислительных шагов, по которым идет усреднение.
* `range` - радиус взаимодействия. Спины находятся на расстоянии 1, но так как числа с плавающей точкой нельзя сравнивать напрямую, рекомендуется указывать радиус немного больше.
* `seed` - начальное значение генератора псевдослучайных чисел, для воспроизводимости результата.
* `temperature` - список температур, для которых выполнять вычисления
* `boundaries` - указываем тип граничных условий.
* `size` - размер системы, через который повторять 

Также в примере есть файл `ising_16_full.ini` с большим набором температур для удобного построения теплоемкости, и дополнительные параметры для вычисления намагниченности.

# 3. Запуск вычислений

Программа запускается командой `metropolis ising_16_simple.ini`. Вывод программы сохранен в файле `ising_16.out`.
